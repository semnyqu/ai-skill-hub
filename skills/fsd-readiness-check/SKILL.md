# FSD AI 开发准入评估 Skill

判断 FSD 是否可交给 AI 自主开发，输出 **PASS / FAIL** 二态结果。报告长度严格控制。

## 核心原则

1. **门禁制**：任一 P0 违规 → FAIL
2. **客观可执行**：字段存在性 + 字面量 + 正则模式
3. **快速失败**：FSD 识别失败立即 FAIL；P0 违规立即输出
4. **不修改 FSD**：只读评估
5. **无问询模式**：路径缺失直接 FAIL，不弹窗
6. **报告精简**：每条违规 1 行，整体长度受控
7. **单文件评估**：一次评估一份 FSD
8. **自动判定模式**：按 FSD 内容特征自动识别前端/后端，全栈 FSD 拒绝评估

## 兼容性声明

本 Skill 设计对齐 **prd-to-fsd v21+ 生成的 FSD**（前端 6 section，后端 8 section，包含 `project`/`repositories` 多仓库元数据）。旧版仅含顶层 `branch` 的 FSD 会因缺少新仓库字段而 FAIL，需先升级 YAML 摘要。

## 输入处理

### 路径解析

| 输入形式 | 处理 |
|----------|------|
| 绝对路径 `/path/to/fsd.md` | 直接使用 |
| 相对路径 `docs/fsd/in91-fsd.md` | 基于当前工作目录解析 |
| `~/...` 形式 | 展开 home 目录 |

**仅支持单文件**：输入为目录路径时直接 FAIL，提示"请提供单个 FSD 文件路径"。

路径缺失输出：
```
❌ FAIL：未提供 FSD 文件路径
示例：评估 FSD docs/fsd/in91-fsd.md
```

## 工作流程

```
用户提交 FSD 路径
  ↓
R1: 文件可读？
  ├─ NO → ❌ FAIL
  └─ YES ↓
R2: 含 FP- 和 AC-？
  ├─ NO → ❌ FAIL（不是FSD）
  └─ YES ↓
R3: YAML 摘要存在？
  ├─ NO → ❌ FAIL（R3违规，含基于文档章节的暂定模式提示，流程终止）
  └─ YES ↓（R4/R5/R6基于YAML）
R10: 自动判定模式（前端/后端/全栈）
  ├─ 全栈 → ❌ FAIL
  └─ 前端/后端 ↓
R4-R9: P0 红线判定
  ├─ 任一违规 → ❌ FAIL
  └─ 全部通过 ↓
P2 提示 → ✅ PASS
```

### 阶段一：文件读取与 FSD 识别

1. 路径解析。如果是目录 → FAIL "请提供单个 FSD 文件路径"
2. 读取文件（R1）。文件 > 200KB 时仅取前 200KB 参与后续检查
3. FSD 识别（R2）：必须含 `FP-` 和 `AC-`

### 阶段二：解析 YAML 摘要

4. 提取文件中**按字符位置第一个** ```yaml``` 围栏代码块作为 YAML 摘要（R3）
   - R3 FAIL（YAML 不存在或无法解析）→ 输出 FAIL 报告（含 R3 违规 + 基于文档章节的暂定模式提示，标注"仅基于文档章节判定，可能不准确，修复 R3 后重新评估"），跳过 R4-R6

### 阶段三：自动判定模式（R10）

5. 基于已解析的 YAML 字段 + 文档章节扫描，按特征积分制判定模式

**后端特征**（5 项·每命中算 1 分）：

| # | 特征 | 判定方式 |
|---|------|---------|
| BE1 | 全文含 `apis_provided` 关键字 | YAML 全文（不论层级，排除 `#` 注释行）含该字符串 |
| BE2 | 全文含 `apis_consumed` 关键字 | YAML 全文（不论层级，排除 `#` 注释行）含该字符串 |
| BE3 | 全文含 `storage` 关键字 | YAML 全文（不论层级，排除 `#` 注释行）含该字符串 |
| BE4 | 含"接口设计"章节标题 | 匹配正则 `^## .*接口设计` |
| BE5 | 含"性能与容量评估"章节标题 | 匹配正则 `^## .*性能` |

**前端特征**（5 项·每命中算 1 分）：

| # | 特征 | 判定方式 |
|---|------|---------|
| FE1 | 含"UI 操作路径"字面量 | 文档正文（排除代码块）含该字符串 |
| FE2 | 含"UI 操作路径编写规范"小节标题 | 匹配正则 `^### .*UI 操作路径` |
| FE3 | `summary.where` 含前端独有扩展名 | YAML 中 `summary.where` 数组项含 `.tsx`/`.vue`/`.jsx`/`.svelte` 任一扩展名 |
| FE4 | YAML 全文含 `dependencies` 关键字但不含 `apis_provided` | 全文关键字检查：有 `dependencies` 且无 `apis_provided` |
| FE5 | `summary.what` 或文档功能描述含前端关键字 | 含"页面"/"按钮"/"Toast" 任一关键字 |

**判定规则**：

| 情况 | 判定结果 |
|------|---------|
| 后端 ≥ 1 + 前端 = 0 | 后端 |
| 前端 ≥ 1 + 后端 = 0 | 前端 |
| 双边 ≥ 2 **且双边命中率比值在 [0.5, 2] 之间**（即 min/max ≥ 0.5） | **全栈 → FAIL** |
| 双边 ≥ 1 但不满足全栈阈值 | 按分高的一边处理 |
| 两边都 = 0 | 兜底前端 + P2 提示"未检测到明确前端/后端特征" |

**兜底前端处理**：与普通前端一致，执行所有 P0 规则。

**命中率比值计算**：min(前端分, 后端分) / max(前端分, 后端分)。
- 前端 2 + 后端 2 → 比值 1.0 → 全栈 ✅
- 前端 2 + 后端 3 → 比值 0.67 → 全栈 ✅
- 前端 2 + 后端 4 → 比值 0.5 → 全栈 ✅（临界值）
- 前端 2 + 后端 5 → 比值 0.4 → 按后端处理（前端是偶然提及）

### 阶段四：P0 红线判定

6. 按 R10 判定的模式加载对应检查清单
7. 按 R4 → R5 → R6 → R7 → R8 → R9 顺序逐项检查，收集所有 P0 违规
8. 任一违规 → FAIL 报告，结束

### 阶段五：P2 提示（可选）

9. P0 通过时输出 PASS 报告 + P2 提示

## P0 红线（10 项·任一违规=FAIL）

具体规则见按模式加载的检查清单：
- 前端：`references/checklist-frontend.md`
- 后端：`references/checklist-backend.md`

### 概要索引

| # | 检查项 | 核心判定 |
|---|--------|---------|
| **R1** | 文件可读 | 文件存在 + 内容（去除控制字符后）≥ 100 字符 |
| **R2** | FSD 文件识别 | 含 `FP-` 和 `AC-` 两个标识 |
| **R3** | YAML 摘要存在 | 按字符位置第一个 ```yaml``` 围栏块可解析为键值对 |
| **R4** | YAML 核心字段非空 | `name`、`branch`、`project.id`、`project.repository`、`repositories`、`entry_points`、`summary.where` 全有且非空 |
| **R5** | Git 仓库元数据有效 | 各仓 `id/branch` 非占位且 ID 唯一；仅一个主仓；`project.repository` 和顶层 `branch` 与主仓一致 |
| **R6** | 代码入口非占位 | 每项长度 ≥ 3 + 不匹配中文占位符 |
| **R7** | 功能点章节存在 | 含 `功能点`/`功能列表`/`功能描述`/`功能清单` 任一关键字的 `##` 章节存在 + 正则 `FP-\d+` 匹配行 ≥ 1 |
| **R8** | 验收标准章节存在 | 含 `验收`/`测试` 任一关键字的 `##` 章节存在 + 正则 `AC-\d+` 匹配行 ≥ 1 |
| **R9** | 接口章节存在 | 含"接口"二字的 `##` 章节存在，内容去除空白后 ≥ 5 字符 |
| **R10** | 模式自动判定 | 按特征积分自动识别前端/后端；全栈（双边 ≥ 2 且命中率比值 ≥ 0.5）→ FAIL |

## R4/R5 YAML 仓库字段为什么是强门禁

| 字段 | AI 开发依赖 |
|------|------------|
| `name` | 区分需求身份 |
| `project.id` | 关联正确业务项目，避免同名仓库串项 |
| `project.repository` | 明确主仓，供默认执行入口和兼容消费者使用 |
| `repositories[].id/branch` | 让多仓需求逐仓切换到正确分支 |
| `repositories[].primary` | 保证整份 FSD 只有一个默认主仓 |
| `branch` | 兼容字段，必须等于主仓分支 |
| `entry_points` | 知道改哪个类/方法 |
| `summary.where` | 知道改哪个文件 |

其他字段影响开发策略但不影响"能否开始开发"，列入 P2。

## 占位符与未确认标记判定方法

R5/R6 检查 YAML 字段，全文检查未确认标记。R5 对顶层 `branch`、`project.id`、`project.repository` 和每个 `repositories[].id/branch` 使用相同的占位符规则。

**检查范围**：
- ✅ 文件中按字符位置**第一个** ```yaml``` 围栏代码块
- ✅ Markdown 正文区域
- ❌ 其他 ``` 围栏代码块（jsonc/text/bash/yaml 配置示例等）

**代码块边界**：仅识别**三个反引号** ``` 围栏，不识别 `~~~`、缩进代码块。

**性能保护**：文件 > 200KB 时仅扫描前 200KB。

**所有长度判定**先去除 ASCII 控制字符（`\u0000-\u001F`、`\u007F`）和零宽字符（`\u200B-\u200D`、`\uFEFF`），再判定。全角空格 `\u3000` 和不间断空格 `\u00A0` 视为空白字符。

**违规模式**：

1. **模板占位符模式**（两级判定）：
   - **中文占位符** `\{[一-龥][^{}]*\}` → **R5/R6 FAIL**
   - **非中文占位符** `\{[A-Za-z0-9][^{}]*\}` → **P2 提示**（如 `{env}`/`{1}`，可能是合法引用）
2. **未确认标记字面量**（大小写不敏感，正文检查）：
   - `未确认`、`待确认`、`待补充`、`待定`、`暂无`
   - `TBD`、`TODO`、`FIXME`、`PENDING`
   - `等待产品确认`、`等待后端确认`
   - `???`、`？？？`

## R9 "无接口变更"声明字面量

R9 接口章节内容匹配以下任一字面量即视为合法：

```
本次需求无接口变更
接口无变更
无接口变更
不涉及接口变更
不涉及接口改动
纯客户端逻辑变更

```

## 输出格式（严格控制长度）

### PASS 报告（≤ 16 行）

```markdown
# FSD 准入评估报告

**结果**：✅ PASS
**FSD**：{fsd_path}
**模式**：{前端|后端}（命中：{编号} {简述}、{编号} {简述}...，共 {N} 项）
**评估时间**：{YYYY-MM-DD HH:mm}（使用 `bash date '+%Y-%m-%d %H:%M'` 获取系统时间）

## ✅ 评估摘要

- P0：10/10 通过
- 功能点：{N} 个 | 验收标准：{N} 条
- 代码入口：{entry_points}

## ⚠️ 建议优化（如有）

- **{rule_id}**：{一句话建议}
```

**P2 提示控制**：≥ 5 项时仅列出前 5 项 + "（还有 N 项省略）"。

### FAIL 报告（≤ 30 行）

```markdown
# FSD 准入评估报告

**结果**：❌ FAIL
**FSD**：{fsd_path}
**评估时间**：{YYYY-MM-DD HH:mm}（使用 `bash date '+%Y-%m-%d %H:%M'` 获取系统时间）

## 不通过原因

- **{rule_id}**：{问题} → {修复建议}
...

**总结**：违规 {count} 项（{rule_id 逗号列表}）
```

**长度控制规则**：
- 每条违规仅 1 行
- FAIL 报告不混入 P2 提示
- 违规项 > 10 时仅列前 10 项 + "（还有 N 项省略）"

### 全栈 FSD 拒绝报告

```markdown
# FSD 准入评估报告

**结果**：❌ FAIL
**FSD**：{fsd_path}
**评估时间**：{YYYY-MM-DD HH:mm}（使用 `bash date '+%Y-%m-%d %H:%M'` 获取系统时间）

## 不通过原因

- **R10**：本 FSD 同时含前端特征（命中：{前3个特征，编号+简述}，{共N项}）和后端特征（命中：{前3个特征，编号+简述}，{共N项}）→ 建议拆分为两份独立 FSD（前后端分别交付）
```

## 交互原则

- **无问询模式**：不使用 `question` 工具
- **快速失败**：识别失败/P0 违规立即 FAIL
- **精简报告**：每条违规 1 行，整体长度受控
- **不修改 FSD**：只读评估
- **单文件评估**：不支持批量，目录路径直接 FAIL
- **自动判定模式**：用户不需要手填 domain；全栈 FSD 拒绝评估
