# 后端 FSD 准入检查清单（P0）

## P0 红线（10 项·任一违规=FAIL）

| # | 检查项 | 判定规则 | 修复建议 |
|---|--------|---------|---------|
| **R1** | 文件可读 | 文件存在 + 内容（去除控制字符后）≥ 100 字符 | 确认 FSD 文件路径有效且非空 |
| **R2** | FSD 文件识别 | 含 `FP-` 和 `AC-` 两个标识 | 确认提供的是 FSD 文件，不是 PRD 或其他文档 |
| **R3** | YAML 摘要存在 | 按字符位置第一个 ```yaml``` 围栏代码块可解析为键值对 | 在 FSD 文件顶部添加 YAML 摘要代码块 |
| **R4** | YAML 核心字段非空 | `name`、`branch`、`project.id`、`project.repository`、`repositories`、`entry_points`、`summary.where` 全有且非空 | 按新版仓库元数据规范填写缺失字段 |
| **R5** | Git 仓库元数据有效 | repositories 至少一项且 ID 唯一；每项 `id/branch` 长度 ≥ 3 且非占位；必须且只能有一个 `primary: true`；`project.repository == 主仓.id`；`branch == 主仓.branch` | 修正仓库 ID、分支和主仓映射，单仓也必须填写 repositories |
| **R6** | 代码入口非占位 | 每项长度 ≥ 3 + 不匹配中文占位符 | 填写实际类名.方法名 |
| **R7** | 功能点章节存在 | 含 `功能点`/`功能列表`/`功能描述`/`功能清单` 任一关键字的 `##` 章节 + 正则 `FP-\d+` 匹配行 ≥ 1 | 添加功能点章节并填写 `FP-001` 等编号行 |
| **R8** | 验收标准章节存在 | 含 `验收`/`测试` 任一关键字的 `##` 章节 + 正则 `AC-\d+` 匹配行 ≥ 1 | 添加验收标准章节并填写 `AC-001` 等编号行 |
| **R9** | 接口章节存在 | 含"接口"二字的 `##` 章节存在，内容去除空白后 ≥ 5 字符 | 添加接口章节，纯定时任务/纯数据变更可填"本次需求无接口变更" |
| **R10** | 模式自动判定为后端 | 后端特征 ≥ 1 分 + 前端特征 = 0 分；双边 ≥ 2 且命中率比值 ≥ 0.5 时判为全栈 → FAIL；其他情况按分高一边处理 | 确认本 FSD 是后端需求 |

## P2 提示（仅 PASS 时·非阻塞）

| # | 提示项 | 判定规则 |
|---|--------|---------|
| **I1** | FSD 元数据完整 | `fsd_version`、`generated_at`、`prd_version`、`priority` 已填 |
| **I2** | 范围合理 | `summary.where` ≤ 3；FP ≤ 15；AC ≤ 30 |
| **I3** | 测试范围明确 | `test_scope` 非空 |
| **I4** | 验收覆盖率 | AC 数 ≥ FP 数 |
| **I5** | Then 无模糊措辞 | 全文正文不含 `正常`/`正确`/`符合预期`/`即可`/`无误`/`没问题` |
| **I6** | FP/AC 章节描述充分 | 功能点章节 + 验收标准章节总字符数 ≥ 200 |
| **I7** | 非中文占位符确认 | R5/R6 字段含非中文占位符（如 `{env}`/`{1}`）→ 提示确认是否为模板残留 |
| **I8** | YAML 格式建议 | 检测到 flow style → 建议改为 block style 以提升可读性 |
| **I9** | 性能评估章节存在 | 含"性能"二字的 `##` 章节存在且非空 |
