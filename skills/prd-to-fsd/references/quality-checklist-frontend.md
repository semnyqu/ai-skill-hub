# FSD 质量检查清单

生成 FSD 后，逐项检查最终交付的 FSD 文件，确认产物质量。全部通过后方可交付。

> 注意：本清单只检查可在 FSD 文件中验证的产物质量，不回顾过程性步骤（如"是否做了访谈"由 AI 在执行中保证）。

---

## 核心检查（15 项）

- [ ] 1. YAML 结构化摘要已填写：name、type、branch、priority、project(id/repository)、repositories、summary(what/where/impact)、entry_points、dependencies、test_scope、is_new_feature
- [ ] 2. 仓库元数据一致：repositories 至少一项且 ID 唯一、仅一个 primary=true、project.repository/顶层 branch 分别与主仓 id/branch 一致；各仓分支与代码探索实际使用的分支一致
- [ ] 3. FSD 版本、生成时间、PRD 版本已在 YAML 摘要中填写
- [ ] 4. 所有代码入口路径均通过实际搜索确认（非猜测），精确到 `文件路径:行号`
- [ ] 5. 接口字段名、类型、枚举值与代码定义一致，嵌套 JSON 已展开说明
- [ ] 6. 每个新增/修改/删除功能点都有对应的验收标准，验收标准覆盖正常/异常/边界/回归
- [ ] 7. Then 无"正常""正确""符合预期"等模糊措辞
- [ ] 8. UI 操作路径：有 UI 自动化时填写，无 UI 自动化时标注"无 UI 自动化测试"
- [ ] 9. AI 自主决策的差异项（字段名/类型不一致）已在第 3 章 3.5 注意事项中注明，格式"PRD 称 X，代码实际 Y，以代码为准"
- [ ] 10. 性能影响、兼容性已在第 3 章 3.5 注意事项中说明；上线保障（灰度/回滚/监控/回归）已在第 4 章功能点边界处理中注明
- [ ] 11. FSD 中无"未确认"标记遗留
- [ ] 12. FSD 输出到 `docs/fsd/{需求简称}-fsd.md`
- [ ] 13. 功能点描述是可执行的规则，无"优化体验""提升效率"等模糊描述
- [ ] 14. 临时文件已清理：`.tmp/prd-to-fsd/` 已删除（如曾触发补全访谈）
- [ ] 15. git 工作环境已恢复（原分支 + stash apply）
