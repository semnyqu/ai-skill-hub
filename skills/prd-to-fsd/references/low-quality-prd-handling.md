# 低信息量 PRD 处理范例（前后端通用）

> 当 PRD 信息严重不足时，Skill 通过 B 档补全访谈 + 代码辅助验证机制处理并生成 FSD。本范例展示前端和后端两个场景。

---

## 场景 A：前端低质量 PRD

**用户输入**：`帮我生成 FSD，分支 feature/xxx，PRD 在 /tmp/prd.md`

**PRD 内容**：
```
需求名称：IN91 校验
需求描述：电商件禁选电话号码，要校验一下。
```

**处理过程**：

1. **信息完整性判定**：1.2 节检查 → 缺需求名称（无显式标题）、功能描述（字符数 < 50）、接口/数据、验收标准 → B 档，进入 1.3 补全访谈
2. **轮次 1·业务定位**：用户在 question 中选"要解决的业务问题"+"用户/系统的核心动作" → AI 追问 → 用户回复"电商件揽收时，SOP 禁选电话号码，但小哥记忆带入时可能带上，需要校验"
3. **轮次 2·技术定位**：用户在 question 中选"代码模块/类名"+"关键字段名" → AI 追问 → 用户回复"IN91 相关的 add-service 模块" → AI 代码辅助验证：搜索 `IN91` → 找到 3 处候选 → 多候选 question 让用户选 → 确认 `AddServiceIN91.handleRecommendResultPersonal`；搜索 `attribute3` → 找到 `AddServiceBean.attribute3`
4. **轮次 3·验收定位**：用户在 question 中选"用户操作 X 后能看到 Y"+"在某场景下系统不做某事" → AI 追问 → 用户回复"电商件扫描时 IN91 被取消勾选并弹 Toast，非电商件不被影响"
5. **访谈成功** → 生成 enriched PRD → 阶段二代码探索（基于已验证入口深度追踪）→ 生成前端 FSD

---

## 场景 B：后端低质量 PRD

**用户输入**：`生成后端 FSD，分支 feature/order-cancel，PRD 在 /tmp/order.md`

**PRD 内容**：
```
需求：订单超时自动取消
说明：太久不付款的订单要自动取消掉
```

**处理过程**：

1. **信息完整性判定**：1.2 节检查 → 需求名称满足、功能描述满足（"订单超时自动取消"，字符 ≥ 50 由后续描述补足）；缺接口/数据、验收标准 → B 档，进入 1.3 补全访谈（仅轮次 2、3）
2. **轮次 2·技术定位**：用户在 question 中选"代码模块/类名"+"关键字段名" → AI 追问 → 用户回复"order-service 的超时取消逻辑，t_order 表" → AI 代码辅助验证：
   - 搜索 `order` + `timeout` + `cancel` → 找到 `OrderTimeoutTask.scanAndCancel` 和 `OrderService.cancelByTimeout` → 多候选 question 让用户选改造入口
   - 搜索 `t_order` → 找到 entity `OrderEntity.java`
3. **轮次 3·验收定位**：用户在 question 中选"接口返回 Z 时系统行为是 W" → AI 追问 → 用户回复"扫描任务执行后，30 分钟未支付的订单状态变为 CANCELLED，库存释放"
4. **访谈成功** → 生成 enriched PRD → 阶段二代码探索（追踪调用链：定时任务 → 订单服务 → 库存服务 → MQ）→ 生成后端 FSD

---

## 关键原则

- **B 档访谈实时结合代码搜索**：用户给的模糊关键词通过代码辅助验证当场消解为精确入口，不再依赖用户事后补充
- **前后端机制完全一致**：访谈三步法（question 选方向 + 对话追问 + 代码辅助）和分档规则相同
- **差异仅在产物**：前端生成 6 section FSD，后端生成 8 section FSD（含性能/容量评估）
